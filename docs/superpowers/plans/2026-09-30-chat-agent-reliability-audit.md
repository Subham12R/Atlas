# Chat and agent reliability — audit and implementation plan

Status: audit/plan only; no chat or server behavior changed in this pass. This follows the existing [agentic-tools design](../specs/2026-09-29-agentic-tools-design.md) and [multi-mode spec](../specs/2026-09-29-atlas-multi-mode-assistant-design.md). Do not confuse the earlier implementation plans' historical checkboxes with current runtime behavior.

## Objective and evidence

Make research/plan/safe-tool turns functional and truthful end to end, then replace chat presentation with beUI at the actual event seams; tighten the macOS-style controls without shrinking their hit targets. Acceptance: a recorded, offline fixture can drive prompt → policy/adapter → tool/approval events → rendered activity, evidence and final answer, and the title-bar control centers visually match the screenshot's intended compact grouping.

- Supplied screenshot: three traffic lights are separated by roughly 72 image pixels between centers (~36 CSS pixels at a 2× capture), much wider than macOS's compact ~20 CSS-pixel center pitch. `TitleBar.tsx` uses 28px targets **plus** 8px flex gap. Keep at least 28px hit targets; overlap target boxes or use positioned dots rather than just shrinking controls. Icon and Atlas wordmark follow the buttons.
- Supplied `chat.pdf` (2 pages): two assistant turns show `Error: agent run failed`, later turns give purported search results without visible source cards or trace. The PDF doesn't include model, selected mode, redacted SSE, or backend logs, so its exact failure cause is **unproven**. Do not repeat the person-specific conversation as a test fixture; use a public synthetic query.
- Reproduced offline: `cd server && .venv/bin/python - <<'PY' ... run_selected(AgentTurnRequest(prompt='Find public sources', mode='tools'), LocalFixture(...)) ... PY` fails with `selected model does not support native tool calls`. This is the minimal red-capable test seam for requesting safe tools with a local adapter; the current UI also disables that choice. `cd server && .venv/bin/python -m unittest tests.test_agent_loop tests.test_agent_stream -q` passed 13 tests, which exercise native-capable fixtures, not this desired fallback.
- Existing UI tests (`apps/desktop/src/renderer/src/pages/Home.test.tsx`, `components/ChatArea.test.tsx`) assert mode submission and chat layout, not an actual research/tool stream rendered through the Home state and ChatArea.
- The later screenshot confirms **Tools** beside **Auto** is confusing duplication: the two controls can be selected simultaneously, but Tools requests a native read-only tool loop while Auto routes *ordinary chat*. User requests **one combined choice**, not just persistent separate controls. `PromptBox.handleSend` explicitly resets selected tool, execution mode and draft format after every send (`chatgpt-prompt-input.tsx`); its empty-chat and populated-chat instances are also separate mounts. The current `chatgpt-prompt-input.test.tsx` tests the old reset; replace that expectation when changing behavior.
- `chat1.pdf` was examined as a 27-page PDF: several turns report `No permitted text model matches the mode and model preference`, one image action was sent to a provider without image generation, a short follow-up about a portfolio produced generic portfolio-search results, and a long technical answer printed `####` literally. Much of the long paper has no source-ID citations, while earlier person-specific claims use combined markers such as `[S1, S3]` whose links/source footer do not match the renderer's single-token `[S1]` parsing. The PDF is a UI/export artifact, not proof that those claims are true or that a web lookup ran. Do not use the named individuals in tests.
- Additional heading report: `ChatArea.tsx:parseMarkdownContent` recognizes only `# `, `## `, `### ` at column zero. `#### 3.3 Advanced Aspects of Dynamic Tool Calling` renders as plain paragraph; `### ` currently produces an `h3` but uses the same `text-sm` size as body paragraphs, so appears minimally differentiated. Indented headings also render literally. Confirm the exact affected input with a renderer fixture before choosing supported Markdown syntax.

## Boundary audit (current worktree)

1. **Capability/route mismatch.** `server/adapters/local_adapter.py` and `openrouter_adapter.py` explicitly advertise no native calls; `server/agents/runner.py:run_tool_loop` rejects them. `ChatArea.tsx` checks `/providers`' `tool_models` and disables the `safeTools` picker for these models. OpenAI/Anthropic/Gemini support only advertised model slugs, not arbitrary custom slugs. Native calls do exist for supported models; claiming they do not exist at all would be incorrect. The specs call for a bounded, explicit workflow fallback, never simulated native function calls or unrestricted local probing.
2. **Why error diagnosis stalls.** `server/api.py:agent_stream` converts all non-Tavily exceptions to `run.failed: agent run failed`; `lib/api.ts:sendAgentStream` turns that into a 502 and Home displays the same generic error. The PDF's two failures could be provider, planner, invalid event, budget, or a tool error; no safe error code/run phase is surfaced. Keep SDK secrets and fetched bodies out of events/logs.
3. **UI loses agent state.** `Home.tsx:handleAgentEvent` preserves sources, queries, `runPhase`, and final content but discards tool-completed history, call IDs, approvals, and step timings. `ChatArea.tsx:SearchTrace` synthesizes a retrospective source list from final metadata rather than displaying what actually happened; no message trace persists for reopen/export. `approval.required` exists in Python/TS schemas, but no production emitter, response endpoint, or pending approval state exists. Do not render an approval card that cannot actually approve/deny.
4. **Reasoning label is misleading.** `ChatArea.tsx` has a `ThinkingBlock` that requires `message.thinking`, but neither Home nor the backend supplies it. Plan mode emits a user-visible outline, not private reasoning. Research has `plan.ready` and tool events; these should feed an **activity** disclosure, not a purported chain-of-thought viewer. Do not fabricate hidden thoughts.
5. **Streaming is split.** Plain chat streams tokens from `/messages/stream`. The agent endpoint emits progress but `run_selected` usually emits a single final `assistant.delta` after synthesis, so beUI's streaming response cannot invent token-by-token agent output. Streaming/partial states must correspond to actual server events; final citation validation must not be bypassed.
6. **Citations and media.** Research validates source ID existence, not claim entailment. `ChatArea.tsx` currently parses inline `[S#]` links and displays cited `Sources`; selected-file refs are separate text. Image generation is an explicit endpoint/action and already has an in-flight skeleton; it is not model-authorized image generation. Existing highlighted code renderer and custom prompt composer support attachments/microphone/modes; replacement must retain these behaviors.
7. **Composer and routing contract.** `selectedTool`, `mode`, and `draftKind` live inside `PromptBox`, reset on submit, and are lost when the empty-chat input is replaced by the active-chat input. `Home.tsx` chooses `agentMode = modeForTool(selectedTool)`, so `Auto + Tools` is *not* two cooperating policies; the tool selection bypasses ordinary Auto routing. When Auto's classifier returns Research but no explicit tool was chosen, the turn still uses ordinary `/messages/stream` (no web evidence). This can produce an unsourced long 'research paper' despite the Research label. Replace the two selectors with one explicit per-chat **intent** (Auto/no web tools, Coding, Documentation, Web search, Research web, Plan, Draft, Safe tools, Generate image). Collapse the old Write/Code entry into Coding; map each intent to existing backend modes/actions at one policy boundary. Do not make Auto silently grant external network access. Persist visible intent for the current chat across replies and the first-turn remount; clear prompt/attachments and one-shot image action. Default a new chat to Auto, and block invalid model/action combinations with a reason before dispatch. Preserve old JSON request shapes at the HTTP boundary until deliberately migrated; no permission token may persist across chats, sessions, or app restarts.
8. **Evidence and answer-quality contract.** A search turn passes the raw `body.prompt` to `web_search` even when it contains an unresolved 'his/her/that' follow-up; `request.recent` is not consulted in that path. Reject/clarify ambiguous pronoun-only search queries or resolve them from explicitly permitted public context *before* sending to Tavily, never disclose private Brain/attachment text to external search. A selected Research-web turn should return concrete, cited findings or say which evidence is missing; a plain Auto turn must not imply it researched the web. `server/agents/research.py:CITATION` matches only `[S1]`/`[A1]`, not grouped `[S1, S3]`; `ChatArea.tsx` similarly links only individual markers and hides sources absent exact `[S1]`. Normalize supported grouped citations into individual valid IDs at the evidence boundary and test unknown/unsupported IDs; never turn an ID-only structural check into a claim of factual verification. Audit PDF/export citation parity. Repeated personalization salutations and sweeping unattributed claims are output-quality issues to evaluate against recorded fixture prompts; do not 'fix' missing evidence with more confident wording.
9. **Markdown contract.** The hand-written parser covers headings 1–3, one form of code fences, lists and tables; changing typography alone cannot parse level 4 or indented headings. Add a behavior check at the `ChatArea` render seam for `###` and `####` in complete and streaming replies, and for literal `####` inside code fences. Preserve inline citations and code highlighting; export (`chatToHtml`/PDF) needs a separate parity check if it parses Markdown independently.
10. **Tool inventory.** Registered read-only actions: `web_search`, `fetch_page` (server-issued source ID), scoped `memory_search`, `search_attached_files`, `read_attached_file`. Search, bounded Research, Plan, Write-style, Draft, explicit image generation and explicit save are workflows/actions. Missing from the earlier design: bounded calculator and source comparison. `citation_check` is deterministic validation, not a model-invokable tool. No arbitrary shell, private browser, remote plugin auto-install, or silent writes: those require a separate trust/sandbox/consent design. A beUI MCP connection supplies **UI source code** only; it is not a user-granted agent tool server.

## Ranked hypotheses for the PDF's generic failures (not yet confirmed)

1. **Unsupported selected model/capability:** if the turn selected Safe Tools with an unsupported model, changing only to an advertised tool-capable model or an explicit Search/Research workflow eliminates `run.failed`. The local fixture confirms the backend rejection path, not that these PDF turns took it.
2. **Provider/model failure during planning or generation:** if so, the same request with a fake working provider succeeds while the real provider produces a safe `provider_unavailable` phase/code. A PDF excerpt alone cannot distinguish this from a bad provider key/model slug.
3. **Validation or event serialization failure:** if so, an offline provider fixture with the same event shape fails at `AgentEventAdapter.validate_python` or message conversion before the final event, and a minimal valid event succeeds.
4. **Search/fetch timeout or tool budget:** if so, an injected delayed/over-budget read reproduces a typed timeout/budget failure; an immediate bounded fixture completes. An absent Tavily key is less likely to explain the **generic** message because `api.py` currently preserves that specific reason.

These are triage leads, not claimed root causes. Test with redacted run ID/mode/provider and safe phase codes, never raw credentials or the private query.

## Ordered delivery slices (one PR/checkpoint each)

### 1. Truthful failure and capability boundary — before UI replacement

- Add a small stable `run.failed` code/phase union at the server event boundary (unsupported model, key unavailable, provider unavailable, validation, timeout, budget, cancelled, internal failure); log a correlated run ID with redacted details server-side. Keep full exception strings, credentials, prompts, and URLs out of renderer events. Handle each code in `lib/api.ts`/`Home.tsx` with an actionable degraded/error state, not a generic bubble. Preserve one final persisted user/assistant turn on successful runs.
- Decide policy for native-unsupported models: retain the strict disablement for **model-chosen** safe tools; expose explicitly selected read-only Search/Research (already server-owned), and if a general Safe Tools action is required for local/OpenRouter, introduce an explicit **bounded server-planned workflow** using only the existing registry, not pretend native calls are supported. Never widen the default Auto chat grant. Test with local and OpenRouter fixtures, and native-capable fixtures; invalid tools and disallowed/private-source disclosure fail closed.
- Repro/acceptance: same offline local fixture no longer ends in an opaque failure on an offered workflow; unsupported autonomous tool selection states why it is disabled. Replay a synthetic agent stream through `sendAgentStream` and assert code/phase propagation. Investigate the PDF-specific failure further only with redacted mode/provider/run ID and event log; do not infer cause from its prose.

### 2. Chat composer continuity and Markdown correctness

- Replace separate Tools + Auto controls with one **Intent** selector owned above the two `PromptBox` mount sites, keyed by chat ID (or share one mounted composer). Show exactly one active label and a clear/default Auto choice. Options: Auto (model routing without web tools; may use an explicitly selected cloud model), Coding, Documentation, Web search, Research web, Plan, Draft, Safe tools, Generate image. Collapse Write/Code into Coding; validate unavailable provider/action combinations *before* sending. A selected model that lacks native calls cannot enable Safe tools; Search/Research remain explicit server workflows. Only the current chat's non-sensitive intent stays selected across turns/remounts and back-navigation; new chat defaults to Auto. Clear text/attachments per send, do not persist permission grants or unbounded network/file access. Image generation and save require a separate explicit action each time. Prefer a single typed client intent mapped once to existing mode/tool request fields, with server policy still authoritative. Before implementation, replace the reset test with a red test for first-turn remount, second send, chat switch, model-capability loss, and exactly one selector.
- Parse heading levels 1–6 (including the supplied `#### 3.3 ...`) at the existing Markdown rendering seam; allow standard leading spaces if supported, and do not turn fenced code into headings. Give `###`/`####` distinct readable hierarchy, including during partial streaming. Test cited inline text and export separately. Prefer the existing renderer helper or installed Markdown package if one already covers these cases; no new parser dependency for a few headings unless current parsing fails more generally.
- Acceptance: one selector maps each intent to precisely one backend action; two sends in one chat retain that visible choice without losing prompt clearing; a new chat defaults safely; unsupported tools and image generation never fire; `###` renders a discernible `h3`, `####` an `h4`, and fenced `####` stays code. No UX-visible reset on a response merely because the composer remounted.

### 3. Grounded follow-ups, citation parity, and answer-quality checks

- Reproduce a generic follow-up search with an offline Tavily fixture and a preceding synthetic public subject; prove raw pronoun-only queries are not sent as broad Tavily queries, while private attached-file/Brain content never leaks to search. Resolve only permitted public context, else ask for the subject; do not silently invent identity or credentials. For Auto, explicitly label non-web replies as model knowledge rather than researched evidence; add a cited Research-web fixture with an insufficient-evidence case.
- Normalize bracketed source markers so `[S1, S3]` can resolve only to source IDs actually issued in that run (or reject invalid format and request a bounded repair). Render/export the same linked citations and source cards; reject unknown IDs and don't claim that an ID verifies the underlying fact. Build a small offline answer-quality set measuring concrete supported claims, source access, uncertainty on missing evidence, follow-up subject resolution, and refusal to invent specifics. Capture before/after outputs; no live personal search in tests.
- Acceptance: raw ambiguous follow-ups do not produce generic portfolio/investment search results; a grounded answer cites real source IDs that survive rendering and PDF export; an unsourced Auto answer does not masquerade as a research result; no fabricated specifics are rewarded by fixture checks.

### 4. Event-to-chat state contract, then agent presentation

- Define one persisted, bounded per-message run trace (run ID, mode, ordered activity items keyed by call/source ID, status, safe label, source refs, approval status) shared by `server/tools/contracts.py`, `lib/agent-events.d.mts`, `Home.tsx` and the existing chat persistence. Deduplicate repeated `source.found`; order concurrent tool calls deterministically and never serialize raw tool arguments/page bodies. `run.failed`/cancel/partial stop the active indicator and remain inspectable after reopening. For `plan.ready`, display the public goal/steps only; never attach chain-of-thought.
- Install only the beUI agent components with a real mapped data contract. Start with **agent-activity**, **todo-list** (real plan steps), **tool-result**, **streaming-response**, **citations**, and **code-block** where their props fit actual server events. Replace old equivalents incrementally, preserving keyboard access, copy, source opening, current markdown behavior, attachments, model picker and stop. **prompt-input** migration is a separate slice because the current composer owns attachments, voice, model/mode selection, and queueing; do not lose those controls. **image-generation** is tied to the existing explicit image action and real pending/success/failure states. Use beUI **approval-card/tool-approval** only after slice 3 has a functioning approval API; do not show decorative approvals.
- Acceptance: deterministic RTL fixture renders plan/search/tool progress, failure, citation mapping, streaming partial answer, and saved completed trace; unknown citation IDs do not link. Existing `Home.test.tsx`, `ChatArea.test.tsx`, prompt input tests and image/attachment checks still pass. No generic fake activity is presented when the backend emits none.

### 5. Fill missing safe agent actions and approvals (not placeholders)

- Add a typed bounded `calculator` for deterministic decimal arithmetic with input length/depth/operator limits and error tests; add `compare_sources` over only source IDs already in the current run, returning excerpt-level comparison with disagreements. Keep `citation_check` as deterministic server policy. Add each to the relevant mode allowlist **only after** tests show privacy boundaries, budget, cancellation, and a visible tool result. A tool menu item is not acceptance; actual model/workflow invocation and UI result are.
- For any write/permissioned action, design an invocation-bound approval record: `call_id`, validated display-only summary/effect, expiry, deny/default timeout, and authenticated approve/deny route scoped to that run. Persist only idempotent user-confirmed writes; fail closed on disconnect/restart. Wire beUI tool-approval/approval-card to that contract and prove denial and replay cannot execute a write. Existing explicit Save document remains the default rather than granting model write access.
- No arbitrary execution, shell, filesystem browsing, or dynamic MCP expansion without an isolated sandbox and a separate consent review. `npx skills add`/beUI MCP configuration is for development, not a runtime agent capability.

### 6. Compact chrome and visual finish

- Change `TitleBar.tsx` layout from 28px buttons + 8px gap to ~20px dot center pitch while keeping usable focus/hover targets and `no-drag` around controls. Keep logo/title close to the cluster without crowding it. Compare a 2× screenshot to the supplied image; check narrow window, light/dark themes and maximize/minimize/close by keyboard and pointer. Preserve the existing window IPC contract.
